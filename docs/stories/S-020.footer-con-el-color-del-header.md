# S-020: Footer con el color del header

**Status:** Ready
**Created:** 2026-11-06
**Source:** REQ-004

## Historia de Usuario

**Como** visitante, participante u organizador,
**quiero** que el header y el footer compartan el mismo color y enmarquen la aplicación,
**para** distinguir de un vistazo qué es la plataforma Telescopio y qué es la información de cada
evento.

## Criterios de Aceptación

### CA-1: Mismo color que el header

**DADO** cualquier pantalla con chrome global (todas salvo las de auth, S-06 a S-10)
**CUANDO** se renderiza
**ENTONCES** el footer tiene fondo `--bg-band` (el mismo negro del header) y texto `--text-inverse`.

### CA-2: Contenido del footer

**DADO** cualquier pantalla con chrome global
**CUANDO** el usuario mira el footer
**ENTONCES** ve la marca `TELESCOPIO`, los links `Inicio` (a `/`) y `Eventos` (a `/events`) y el
tagline "Telescopio · evaluación distribuida entre pares"
**Y** los links navegan con el router, sin recargar la página.

### CA-3: Idioma

**DADO** que el usuario cambia el idioma a EN con el selector `ES / EN`
**CUANDO** mira el footer
**ENTONCES** los links y el tagline se muestran en inglés, sin recargar.

### CA-4: Mobile

**DADO** un viewport de 768px o menos
**CUANDO** se renderiza el footer
**ENTONCES** la marca, los links y el tagline se apilan, sin scroll horizontal.

### CA-5: Pantallas de auth

**DADO** una pantalla de auth (login, registro, recuperar contraseña, completar perfil, reset)
**CUANDO** se renderiza
**ENTONCES** no cambia: sigue con su layout dividido propio, sin el footer de `AppLayout`.

### Implementación (referencias)

- `web/src/components/layout/app-layout/AppLayout.tsx` y `AppLayout.css` (`.ly-footer`): hoy fondo
  claro con `border-top: var(--border-default)` y texto `--text-secondary`. Pasa a
  `background: var(--bg-band)`, `color: var(--text-inverse)` y links en `--text-inverse` con foco
  visible (`focus.ring`).
- Tokens existentes del DS `web` v2.1.0 (`src/styles/tokens.css`): no hace falta ninguno nuevo.
- i18n (ADR-010): reutilizar `footer.tagline` y sumar claves para los dos links. Si ya existen
  claves de navegación del header para "Inicio" y "Eventos", reutilizarlas.
- Responsive: mobile-first con el único corte en `768px` (convención `styling`).
