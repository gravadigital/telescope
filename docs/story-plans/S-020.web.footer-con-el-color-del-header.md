# Story Plan: S-020 (web) - Footer con el color del header

## Status

**Status:** Completed

## Story Reference

- **Story:** [S-020](../stories/S-020.footer-con-el-color-del-header.md)
- **Service:** web
- **Source:** [REQ-004](../requests/REQ-004.marco-de-plataforma-y-color-de-portada-del-evento.md)
- **Summary:** el footer de `AppLayout` pasa a tener el mismo fondo negro de banda que el header
  (`--bg-band`), con la marca `TELESCOPIO`, links a Inicio y Eventos y el tagline actual, en ES y EN.
  Header y footer enmarcan la plataforma; el evento se distinguirá por su portada de color (S-021).

## Architectural Context

### Tech Stack

| Pieza | Detalle |
|---|---|
| Framework | React 19 con Create React App (`react-scripts`), SPA sin SSR |
| Router | `react-router-dom` v7 (client-side): `Link`, `Outlet` |
| Estilos | CSS plano, un `.css` por componente; tokens del DS `web` v2.1.0 en `src/styles/tokens.css` |
| i18n | Propio (ADR-010): hook `useT()` de `src/i18n`, catálogos `src/i18n/catalogs/es.ts` y `en.ts` tipados por `Catalog` |
| Tests | Jest (CRA) + Testing Library + `@testing-library/user-event` |
| Lint | `npm run lint` (`eslint --max-warnings=0`), con `react/jsx-no-literals` sobre `src/components/layout/**` |

### Service Architecture

```
web/src/
├── App.tsx                                  # AppRoutes: rutas con <AppLayout /> y rutas de auth fuera
├── routes.test.tsx                          # tests de rutas (TS-55: auth fuera del chrome global)
├── components/layout/
│   ├── app-header/AppHeader.{tsx,css,test.tsx}   # banda global (patrón a imitar)
│   ├── app-layout/AppLayout.{tsx,css}            # header + <main> + footer (footer hoy inline)
│   └── app-footer/                               # NUEVO: AppFooter.{tsx,css,test.tsx}
├── i18n/catalogs/{es,en}.ts                 # claves nav.*, common.appName, footer.tagline
├── styles/tokens.css                        # tokens del DS (no se toca)
└── test-utils/renderWithProviders.tsx       # MemoryRouter + I18nProvider + auth mockeado
```

**Reglas de las convenciones activas:**
- **`project-structure`:** un componente por carpeta en kebab-case con su `.tsx`, `.css` y
  `.test.tsx`; componentes de chrome global en `components/layout/`.
- **`styling`:**
  - CSS plano, un archivo por componente, importado desde su `.tsx`;
  - clases con el prefijo del componente (`ly-` para el layout);
  - **los tokens viven solo en `src/styles/tokens.css`**: ningún hex en los componentes;
  - **mobile-first**: la regla base es mobile y un único corte `@media (min-width: 768px)`, sin
    `max-width`;
  - contenedor de 1200px.
- **`routing`:** navegación interna con `Link` de `react-router-dom`; nunca `<a href>` a rutas de la
  SPA.
- **`testing`:** Testing Library por rol accesible; IDs de escenario (`TS-n`) en el nombre del test;
  `renderWithProviders(ui, { locale, auth, route })` con `jest.mock('../../../context/AuthContext')`.
  El CSS se verifica leyendo el archivo con `fs` (jsdom no aplica estilos), como en
  `AppHeader.test.tsx`.

### Relevant ADRs

- **ADR-007 — CSS plano sin framework.** Un `.css` por componente, tokens como variables CSS. Sin
  Tailwind, CSS-in-JS ni CSS Modules.
- **ADR-010 — i18n propio sobre `Intl`.** Todo texto visible sale de los catálogos `es` y `en` vía
  `t('clave')`; `react/jsx-no-literals` impide strings en el JSX de `src/components/layout/**`.

### UX Context (product-map → "Chrome global")

> **Footer (REQ-004).** Presente en las mismas pantallas que el header. Comparte su fondo `bg.band`
> (negro) con texto inverso: header y footer enmarcan la plataforma, y el evento se distingue por su
> portada de color (hero de S-04 y S-05). Contenido: marca `TELESCOPIO`, links `Inicio` (`/`) y
> `Eventos` (`/events`) y el tagline actual ("Telescopio · evaluación distribuida entre pares"), en
> ES y EN. En `mobile` se apila.

Chrome global presente en todas las pantallas salvo las de auth (`/login`, `/register`,
`/forgot-password`, `/reset-password`, `/complete-profile`), que usan su layout dividido sin barra
ni pie. En `App.tsx` esas rutas ya están fuera de `<Route element={<AppLayout />}>`.

**Viewports:** superficie `web`, `mobile` (base) y `desktop` (≥ 768px).

### Design System Context (`web` v2.1.0)

**Tokens que usa el footer** (`tokens/semantic.md`, `foundations/color.md`):

| Token (CSS) | Valor | Uso en el footer |
|---|---|---|
| `--bg-band` | `color.black` `#000000` | Fondo del footer (el mismo que `.ly-header`) |
| `--text-inverse` | `#FFFFFF` | Texto base y links en hover (21:1 sobre negro) |
| `--text-inverse-secondary` | `color.violet.200` `#CFC9F7` | Links en reposo y tagline |
| `--text-signal` | `color.cyan.400` `#35D6F2` | Marca `TELESCOPIO`, igual que el logo del header |
| `--focus-ring` | `0 0 0 4px #EAE7F9` | Foco visible de marca y links |
| `--type-heading-s`, `--type-ui`, `--type-caption` | — | Marca, links, tagline |
| `--space-padding-compact`, `--space-inline-sm`, `--space-padding-default`, `--ref-space-xl` | — | Paddings y gaps (los mismos del header) |

**Estilo de referencia: links del `AppHeader`** (`AppHeader.css`):
```css
.ly-header { background: var(--bg-band); color: var(--text-inverse); }
.ly-header__logo { color: var(--text-signal); font: var(--type-heading-s);
  letter-spacing: var(--type-tracking-wide); text-decoration: none; }
.ly-header__link { color: var(--text-inverse-secondary); font: var(--type-ui); text-decoration: none; }
.ly-header__link:hover { color: var(--text-inverse); }
.ly-header__logo:focus-visible, .ly-header__link:focus-visible {
  outline: none; box-shadow: var(--focus-ring); border-radius: var(--radius-control); }
```

**DS Gaps:**
- *Aceptados* (revisión UX de REQ-004): **links del footer**, sin componente de DS. Resolución:
  "Dejar anotado"; reutilizan el estilo de los links del `AppHeader`, porque la navegación no está
  componentizada.
- *Nuevos:* ninguno.

### Code to Modify (estado actual)

**`AppLayout.tsx`:**
```tsx
const AppLayout: React.FC = () => {
  const { t } = useT();
  const { user } = useAuth();
  const layout = (
    <div className="ly-layout">
      <AppHeader />
      <main id="main" className="ly-layout__main">
        <Outlet />
      </main>
      <footer className="ly-footer">
        <p className="ly-footer__text">{t('footer.tagline')}</p>
      </footer>
    </div>
  );
  return user ? <NotificationsProvider>{layout}</NotificationsProvider> : layout;
};
```

**`AppLayout.css`** (las reglas `.ly-footer*` se mueven a `AppFooter.css`):
```css
.ly-layout { display: flex; flex-direction: column; min-height: 100vh; background: var(--bg-canvas); }
.ly-layout__main { flex: 1; }
.ly-footer { border-top: 1px solid var(--border-default); padding: var(--space-padding-compact); }
.ly-footer__text { max-width: 1200px; margin: 0 auto; color: var(--text-secondary); font: var(--type-caption); }
@media (min-width: 768px) { .ly-footer { padding: var(--space-padding-compact) var(--ref-space-xl); } }
```
`.ly-layout` ya es columna flex con `min-height: 100vh` y `main { flex: 1 }`: el footer queda al pie
aunque haya poco contenido. No cambia.

**i18n existente:** `common.appName` = `TELESCOPIO`; `nav.home` = `Inicio` / `Home`;
`nav.events` = `Eventos` / `Events`; `footer.tagline` = `Telescopio · evaluación distribuida entre
pares` / `Telescopio · distributed peer review`.

### Task 2: Componente `AppFooter`

**Status:** Completed

#### Description

Extraer el footer a un componente propio, con el color de banda, la marca y los links.

#### Acceptance Criteria

1. `src/components/layout/app-footer/AppFooter.tsx` renderiza:
   ```tsx
   <footer className="ly-footer">
     <div className="ly-footer__inner">
       <Link to="/" className="ly-footer__brand">{t('common.appName')}</Link>
       <nav aria-label={t('footer.nav')} className="ly-footer__links">
         <Link to="/" className="ly-footer__link">{t('nav.home')}</Link>
         <Link to="/events" className="ly-footer__link">{t('nav.events')}</Link>
       </nav>
       <p className="ly-footer__text">{t('footer.tagline')}</p>
     </div>
   </footer>
   ```
2. `AppFooter.css`:
   - `.ly-footer` con `background: var(--bg-band)` y `color: var(--text-inverse)`;
   - `.ly-footer__inner` con `max-width: 1200px; margin: 0 auto;`, en columna en la base y en fila
     desde 768px (`align-items: center`, `gap: var(--space-padding-default)`, tagline empujado a la
     derecha con `margin-left: auto`);
   - marca y links con los estilos de los links del header (ver "Design System Context");
   - tagline en `--text-inverse-secondary` con `font: var(--type-caption)`;
   - `:focus-visible` de marca y links con `box-shadow: var(--focus-ring)`;
   - paddings: `var(--space-padding-compact)` en la base y `var(--space-padding-compact) var(--ref-space-xl)`
     desde 768px.
3. `AppLayout.tsx` renderiza `<AppFooter />` en lugar del `<footer>` inline; las reglas `.ly-footer*`
   salen de `AppLayout.css`.
4. Sin hex literales; sin `@media` con `max-width`.

#### Technical Details

- **Contexto:** convenciones `styling`, `routing`, `project-structure`; ADR-007, ADR-010; gap
  aceptado (links sin componente de DS).
- **Archivos:** `src/components/layout/app-footer/AppFooter.tsx`, `AppFooter.css`,
  `AppFooter.test.tsx` (nuevos); `src/components/layout/app-layout/AppLayout.tsx` y `AppLayout.css`.
- **Notas:** `<footer>` como hijo directo del layout es el landmark `contentinfo`. Si
  `src/components/layout/index.ts` exporta los componentes de layout, sumar `AppFooter`.

#### Testing Requirements

- **Unit:** TS-1 a TS-6 en `AppFooter.test.tsx`.

#### Task Dependencies

**Blocked by:** Task 1 · **Blocks:** Task 3
