# Story Plan: S-021 (web) - EventHero con color de portada configurable

## Status

**Status:** Ready

## Story Reference

- **Story:** [S-021](../stories/S-021.eventhero-con-color-de-portada.md)
- **Service:** web
- **Source:** [REQ-004](../requests/REQ-004.marco-de-plataforma-y-color-de-portada-del-evento.md)
- **Depende de:** S-019 (`cover_color` en la API: `POST` y `PATCH /events`, y en `EventDetail`). La
  rama de S-021 tiene que incluir el código de S-019.
- **Summary:** el encabezado del evento (`EventHero`, en el detalle y en la gestión) deja el negro de
  banda y toma el color de portada del evento, una de 16 pasteles. El organizador lo elige al crear el
  evento (paso 1) y lo cambia desde el diálogo "Editar datos" (O-18); en votación, resultados o con el
  evento cancelado, el diálogo pasa a **modo solo color**.

**Reglas de las convenciones activas:**
- **`styling`:**
  - un `.css` por componente, con prefijo de clase (`ui-` para el kit, `ev-` para eventos);
  - **ningún hex fuera de `tokens.css`**;
  - mobile-first con un único `@media (min-width: 768px)`, sin `max-width`.
- **`project-structure`:** cada componente del kit en `components/ui/{kebab}/` con `.tsx`, `.css` y
  `.test.tsx`, exportado desde `components/ui/index.ts`. Las reglas puras van en `src/domain/` y se
  exportan desde `src/domain/index.ts`.
- **`forms`:** formularios controlados con `useState`; validación en `src/domain/`; el payload del
  `PATCH` lleva **solo lo que cambió** (`changedEventFields`).
- **`testing`:** Testing Library por rol accesible; IDs `TS-n` en el nombre del test;
  `renderWithProviders(ui, { locale, auth, route })`; `jest.mock('../../services/api')` para el
  servicio.

### Relevant ADRs

- **ADR-007 — CSS plano.** Tokens como variables CSS; sin CSS-in-JS. Una variable CSS inline
  (`style={{ '--ev-hero-bg': 'var(--bg-cover-mint)' }}`) es válida: el valor sale de un token.
- **ADR-010 — i18n propio.** Todo texto visible sale del catálogo. Los componentes del kit `ui/`
  **no traducen**: reciben los textos por props (como `NumberStepper`: `label`, `decrementLabel`…).
  El catálogo `es` es español neutro: sin voseo (TS-25 de i18n) y sin marcas de género (TS-27).

### API Context (contrato de S-019)

- **`CoverColor`:** `string`, enum `[lavender, periwinkle, sky, ice, aqua, mint, pistachio, lemon,
  butter, peach, coral, rose, pink, lilac, sand, mist]`, default `lavender`.
- **`POST /api/v1/events`:** el body suma `cover_color` opcional. Respuesta `201 { event: { …, cover_color } }`.
- **`PATCH /api/v1/events/{event_id}`:** el body suma `cover_color`. **Si el body trae solo
  `cover_color`, se acepta en cualquier etapa y aunque el evento esté pausado o cancelado.** Con otros
  campos fuera de `creation`/`participation` responde `409 INVALID_UPDATE_STAGE`. Un color fuera de
  la paleta responde `400 INVALID_COVER_COLOR`. `200 { data: EventDetail, code: EVENT_UPDATED }`.
- **`EventDetail` / `EventListItem`:** suman `cover_color`.
- El catálogo ya traduce `INVALID_COVER_COLOR` ("El color de portada no es válido.").

### Flow Context (`edicion-y-visibilidad-del-evento`, paso 3)

`EditEventDialog` → `PATCH /api/v1/events/{event_id}` con los campos cambiados → `200 EventDetail`.
Desde S-019, en `voting`/`results` (o con el evento cancelado) el diálogo manda **solo**
`{ "cover_color": … }`.

**Tokens semánticos:**
- `bg.cover.{id}` → `color.cover.{id}`;
- `bg.cover.default` → `color.cover.lavender`;
- `bg.band` queda para header, footer y panel de marca.

En CSS: `--ref-color-cover-{id}`, `--bg-cover-{id}`, `--bg-cover-default`.

**Componente `color-swatch-picker`** (spec v2.1.0; la Tarea 7 suma la prop `names`):
- **Anatomía:** label; grilla de 16 botones circulares rellenos con `bg.cover.{id}` en orden
  canónico; ✓ en `text.primary` en la elegida, más un anillo; nombre del color elegido visible bajo la
  grilla; ayuda opcional.
- **Sizes:** desktop, muestra de 32px en 8 columnas; mobile, muestra de 40px con área de 44px en 4
  columnas.
- **States:**
  - default: borde `border.default`;
  - hover: escala 1,08 con `transition.fast`;
  - selected: ✓ y anillo de 2px `bg.action.primary` con 2px de offset;
  - focus: `focus.ring` + `border.focus`;
  - disabled: opacidad 0,4 y `cursor: not-allowed`.
  - No tiene estado de error propio.
- **Accesibilidad:**
  - `role="radiogroup"` con `aria-labelledby`; cada muestra `role="radio"` con `aria-checked`;
  - nombre accesible = nombre del color en el idioma activo;
  - roving tabindex: Tab entra en la seleccionada, las flechas mueven la selección (izquierda/derecha;
    arriba/abajo por fila) y Espacio confirma.
- **Tokens de componente:** `swatchPicker.swatch.size` 32px (mobile 40px, área de 44px),
  `.radius` `radius.full`, `.border` `border.default`, `.gap` `space.sm`, `.columns` 8 (mobile 4),
  `.selected.ring` 2px `bg.action.primary` con offset de 2px, `.selected.check` `text.primary`,
  `.focus` `focus.ring` + `border.focus`, `.disabled.opacity` 0,4.
- **Don't:** colores libres, input de hex, enviar hex a la API.
- **API (v2.1.1):** `value: CoverColorId`, `onChange(id)`, `label`, `help?`, `disabled?` y
  **`names: Record<CoverColorId, string>`**.

**Componentes reutilizados:**
- **`StatusPill`:** tonos `success | warning | action | neutral | onBand`. En el hero se usan los
  tonos por defecto; `onBand` queda para fondos de banda.
- **`Button`:** variantes `primary | secondary | tertiary | onBand | icon`. En el hero, `secondary`.
- **`Dialog`**, **`Callout`** (`tone="info"` para el aviso de solo color) y **`NumberStepper`**.

**DS Gaps:**
- *Aceptados (REQ-004):* ninguno aplica a S-021. Los links del footer son de S-020.
- *Nuevos (aprobados al planificar):*
  - **`Countdown` sobre fondo claro.** Es un componente de dominio, no del DS, y todo su estilo es de
    banda (`--countdown-box-bg: #ffffff14`, dígitos `--ref-color-white`, título `--ref-color-cyan-400`).
  - **Resolución:** variante `tone="light"`, con cajas `--bg-surface` y borde `--border-default`,
