# Story Plan: S-017 (web) - Armado y reenvío del ranking

## Estado

**Status:** Completed

## Referencia de la Story

- **Story:** [S-017](../stories/S-017.armado-y-reenvio-del-ranking.md)
- **Servicio:** web
- **Resumen:** el participante ordena sus propuestas asignadas con ↑ ↓ (posición siempre única),
  las abre sin saber de quién son, el borrador se guarda solo y puede reenviar el ranking hasta el
  cierre; en Resultados lo ve en solo lectura. Reemplaza `RankingVotePanel` (selects) por
  `voting/SortableRankList` y borra el bloque *legacy* de tokens de `styles/global.css`.

## Decisiones tomadas al planificar

Aprobadas por el usuario al revisar la propuesta (2026-10-09). Son vinculantes para la implementación.

- **D-1 — Referencia del ranking enviado (`NOT DOCUMENTED` en la API).** Ningún endpoint devuelve los
  votos enviados: `AnonymousAssignment` solo trae `is_completed`, y el borrador (`vote_drafts`) se
  sigue guardando después del envío. Para saber si el orden "cambió" (CA-6) y qué mostrar en solo
  lectura (CA-8):
  1. Al enviar con éxito, se guarda el orden enviado en `localStorage` con `useLocalStorage`, clave
     `telescopio_submitted_ranking:{assignment_id}` (valor: array de `attachment_id` en orden), **y**
     se hace `PUT …/vote-draft` con ese mismo orden.
  2. **Referencia de lo enviado** (`submitted`) = valor local → si no hay, el borrador (si
     `is_completed`) → si no hay, el orden de la asignación (si `is_completed`). Con
     `is_completed: false`, `submitted = null`.
  3. **Orden en pantalla** = borrador válido → si no, `submitted` → si no, orden de la asignación.
  4. **Limitación conocida:** en otro dispositivo, tras modificar sin reenviar, la referencia puede no
     coincidir con lo enviado de verdad. Resolverlo del todo requiere un endpoint nuevo en `api`
     (fuera del alcance de esta story: "Cambios de API: ninguno").
- **D-2 — Título del ranking en solo lectura (copy `NOT DOCUMENTED` en el screen.md):**
  "Tu ranking" / "Your ranking".
- **D-3 — Votación cerrada mientras tanto (copy `NOT DOCUMENTED`):** un `400` del envío con
  `details.current_stage` distinto de `"voting"` muestra "La votación ya cerró. No se puede modificar
  el ranking." / "Voting has closed. The ranking can no longer be changed." y recarga el detalle en
  silencio (la lista pasa a solo lectura por estar en `results`).
- **D-4 — "Se descarga con su token y se abre en otra pestaña":** en el mismo click se abre una
  pestaña vacía (`window.open('', '_blank')`, sincrónico para no ser bloqueado); después se pide el
  archivo con token (`fetchFile`) y la pestaña navega al `blob:` URL. Si la pestaña no pudo abrirse
  (`null`), se descarga con el nombre neutro `propuesta-{n}.{ext}`. Si el pedido falla, se cierra la
  pestaña abierta y se muestra el error.
- **Discrepancia de documentación:** `docs/flows/evaluacion-y-envio-de-ranking.md` (paso 3) dice
  `POST …/vote-draft` con `assignment_id`; la API (`docs/apis/api.yaml`) y el código usan **`PUT`**
  con body `{ rankings }`. Se sigue la API (no cambia: `VoteDraftService.saveDraft` ya usa `PUT`).

### Contexto de API

Base: `API_CONFIG.BASE_URL`. Auth: JWT Bearer (lo agrega `apiRequest` / `downloadFile`).
Formas de error relevantes: `ApiError {error, code, details?}` (handlers), `LegacyError {error,
details?, current_stage?}` (votación distribuida: **sin `code`**), `MiddlewareError {error: CODE, message}`.

**Constantes existentes en `src/config/api.ts`:**

```ts
GET_ASSIGNMENT: (eventId, participantId) => `/api/v1/events/${eventId}/participants/${participantId}/assignment`,
SUBMIT_RANKING_VOTES: (eventId, participantId) => `/api/v1/events/${eventId}/participants/${participantId}/ranking-votes`,
VOTE_DRAFT: (eventId, participantId) => `/api/v1/events/${eventId}/participants/${participantId}/vote-draft`,
DOWNLOAD_ATTACHMENT: (attachmentId) => …/api/v1/attachments/${attachmentId}/download
```

#### `GET /api/v1/events/{event_id}/participants/{participant_id}/assignment`

Solo el propio participante, el autor del evento o un admin, en etapa **`voting` o `results`**.
Payload anónimo: sin autor ni nombre original, sin campos internos.

- `200`:
  ```json
  {
    "assignment": {
      "id": "uuid", "event_id": "uuid", "is_completed": false, "completed_at": null,
      "attachments": [
        { "id": "uuid", "label": "Propuesta 1", "mime_type": "application/pdf",
          "file_size": 1048576, "description": "texto o null" }
      ]
    },
    "event_name": "string",
    "participant_id": "uuid"
  }
  ```
  `label` = "Propuesta N", N = posición en `attachment_ids` (1-based), en el orden del array.
- `400` `LegacyError` (+ `current_stage`) si el evento no está en `voting` ni `results`.
- `403` `LegacyError`: no está registrado. `404` `ApiError` `NO_ASSIGNMENT`: inscripto sin asignación.

Servicio existente: `DistributedVotingService.getParticipantAssignment(eventId, participantId):
Promise<AnonymousAssignment | null>` (devuelve `null` ante `NO_ASSIGNMENT`). Tiene un `console.log`
que se quita.

#### `GET /api/v1/events/{event_id}/participants/{participant_id}/vote-draft`

- `200`: `{ data: { id, event_id, assignment_id, participant_id, rankings: [{ attachment_id, rank }], created_at, updated_at } }`
- `404` `ASSIGNMENT_NOT_FOUND` / `DRAFT_NOT_FOUND` (esperado cuando no hay borrador). `400`
  `INVALID_PARTICIPANT_ID`. `500` `DRAFT_GET_ERROR`.
- Sin restricción de etapa en el handler (funciona en `results`).

Servicio existente: `VoteDraftService.getDraft(eventId, participantId): Promise<VoteDraftResponse | null>`
— hoy detecta el 404 con `err.message.includes('404' | 'DRAFT_NOT_FOUND')` y `catch (err: any)`:
se corrige a `getErrorCode` (Task 2).

```ts
export interface DraftRanking { attachment_id: string; rank: number; }
export interface VoteDraftResponse { assignment_id: string; participant_id: string; rankings: DraftRanking[]; updated_at: string; }
```

#### `PUT /api/v1/events/{event_id}/participants/{participant_id}/vote-draft`

- Body: `{ "rankings": [{ "attachment_id": "uuid", "rank": 1 }] }`. No valida duplicados ni
  consecutividad (guardado de progreso). Upsert por (asignación, participante). Se acepta con la
  asignación completa mientras el evento esté en `voting` (S-007).
- `200`: `{ message, data: { assignment_id, participant_id, rankings_count, updated_at }, code: "DRAFT_SAVED" }`
- `400` `INVALID_EVENT_ID` / `INVALID_PARTICIPANT_ID` / `INVALID_PAYLOAD` / `INVALID_ATTACHMENT_ID`;
  `404` `ASSIGNMENT_NOT_FOUND`; `500` `DRAFT_SAVE_ERROR`.

Servicio existente: `VoteDraftService.saveDraft(eventId, participantId, rankings: DraftRanking[]): Promise<void>`.

#### `POST /api/v1/events/{event_id}/participants/{participant_id}/ranking-votes`

- Body: `{ "assignment_id": "uuid", "rankings": [{ "attachment_id": "uuid", "rank": 1 }] }` —
  rangos enteros **consecutivos desde 1**, sin duplicados, cada propuesta de la asignación.
- **Reenvío (S-007):** si la asignación ya está completa y el evento sigue en `voting`, reemplaza
  (transacción `DELETE` + `INSERT`) y responde `replaced: true`. Fuera de `voting` → `400`.
- `201` (plano, sin envelope ni `code`):
  `{ "message": "Ranking votes submitted successfully", "event_id": "uuid", "participant_id": "uuid", "votes_count": 3, "replaced": false }`
- `400` `LegacyError`: payload inválido, rangos duplicados/no consecutivos, `assignment_id` que no
  corresponde, propuesta no asignada; **etapa incorrecta → body con `current_stage`** (verificado en
  `api/internal/handlers/distributed_vote_handler.go`: `{"error": …, "current_stage": "results"}`),
  que `ApiError` deja en `details.current_stage`.
- `403` no registrado · `404` evento / asignación / propuesta inexistente · `500` fallo al guardar.

Servicio existente: `DistributedVotingService.submitRankingVotes(eventId, participantId, assignmentId,
rankings: RankingVote[]): Promise<void>` — pasa a devolver `{ replaced: boolean }` (Task 2).

#### `GET /api/v1/attachments/{attachment_id}/download`

Puede descargarla quien la tiene en su asignación del mismo evento en `voting` o `results`.
**Anonimato:** para el evaluador, `Content-Disposition: attachment; filename="propuesta-{n}.{ext}"`.

- `200` binario (`Content-Type`, `Content-Length`). `401`; `403` `FORBIDDEN`; `404`
  `ATTACHMENT_NOT_FOUND` / `FILE_NOT_FOUND`.

Código existente:

```ts
// src/services/api.ts
export const extensionForMime = (mimeType: string): string => NEUTRAL_EXTENSIONS[mimeType] ?? 'bin';
export const neutralFilename = (position: number, mimeType: string): string =>
  `propuesta-${position}.${extensionForMime(mimeType)}`;
AttachmentService.downloadAssignedAttachment(attachmentId, position, mimeType): Promise<void>
  // → downloadFile(DOWNLOAD_ATTACHMENT(id), neutralFilename(position, mimeType))

// src/config/api.ts
export const downloadFile = async (endpoint: string, filename: string): Promise<void> => {
  const url = `${API_CONFIG.BASE_URL}${endpoint}`;
  const token = localStorage.getItem('telescopio_token');
  const response = await fetch(url, { headers: token ? { 'Authorization': `Bearer ${token}` } : {} });
  if (!response.ok) {
    const errorData = await response.json().catch(() => ({}));
    throw new ApiError({ status: response.status, body: errorData });
  }
  const blob = await response.blob();
  const blobUrl = window.URL.createObjectURL(blob);
  const link = document.createElement('a');
  link.href = blobUrl; link.download = filename;
  document.body.appendChild(link); link.click(); link.remove();
  window.URL.revokeObjectURL(blobUrl);
};
```

Mapa `NEUTRAL_EXTENSIONS` (mime → ext): `image/jpeg`→`jpg`, `image/png`→`png`, `image/gif`→`gif`,
`image/webp`→`webp`, `application/pdf`→`pdf`, `text/plain`→`txt`, `application/msword`→`doc`,
`application/vnd.openxmlformats-officedocument.wordprocessingml.document`→`docx`; otro → `bin`.

### Contexto de Flujo

Flujo `evaluacion-y-envio-de-ranking` (Stories S-007, S-009, S-017). Pasos (copiados del flujo, con
la corrección de método del paso 3 según la API):

1. **web → api** `GET …/participants/{participant_id}/assignment` (etapas `voting` y `results`) →
   `200 { assignment: { id, event_id, is_completed, completed_at, attachments[{ id, label, mime_type, file_size, description }] }, event_name, participant_id }`;
   sin asignación → `404 { error, code: "NO_ASSIGNMENT" }`. Las `m` propuestas nunca incluyen la propia.
1b. **web → api** `GET /api/v1/attachments/{attachment_id}/download` → binario con
   `Content-Disposition: propuesta-{n}.{ext}`; propuesta fuera de la asignación o etapa → `403 FORBIDDEN`.
2. **web → api** `GET …/vote-draft` → `200 { data: { rankings } }` o `404` (sin borrador).
3. **web → api** `PUT …/vote-draft` `{ rankings }` (upsert; sin validar consecutividad; aceptado con la
   asignación completa en `voting`).
4. **web → api** `POST …/ranking-votes` `{ assignment_id, rankings }` → transacción `DELETE` + `INSERT`
   → `201 { message, event_id, participant_id, votes_count, replaced }`. Efecto: notificación
   `ranking_submitted` `{replaced}` (S-009).

**Cambios planificados que implementa esta story (sección "Cambios planificados" del flujo):**

| Paso | Cambio |
|---|---|
| 3 | La web guarda el borrador con debounce desde `SortableRankList` |
| Web | Lista ordenable ↑↓ (posición siempre única) en lugar de selects; solo lectura en `results`; copy del mecanismo real |

**Escenario de la story — modificar y reenviar (CA-5 a CA-7):**
1. **[web]** `GET …/assignment` + `GET …/vote-draft` → orden inicial (borrador si existe, si no el de la asignación).
2. **[web — `SortableRankList`]** ↑ ↓ intercambian; cada cambio → `PUT …/vote-draft` con debounce.
3. **[web]** "Reenviar mi ranking" → `POST …/ranking-votes { assignment_id, rankings }`.
4. **[api]** reemplaza en una transacción → `201 { …, replaced: true }`.
5. **[web]** aviso "Recibimos tu ranking." y el botón vuelve a secundario.

**Manejo de errores (story):** falla del borrador → aviso, el orden queda en pantalla · falla del
envío → mensaje traducido, el orden se conserva · `400` de etapa → mensaje traducido (D-3) y la
lista pasa a solo lectura al recargar.

**Al terminar:** mover las filas de "Cambios planificados" del flujo a los pasos correspondientes y
corregir `POST` → `PUT` en el paso 3 (Task 5).

#### Componente: Button (spec v2.0.0, completa)

- **Propósito:** dispara una acción. Cuándo NO: navegación sin acción → link; acción solo icónica → `variant="icon"` con `aria-label`.
- **Anatomía:** Container (`radius.control`) · Label (verbo + objeto) · Icono opcional · Indicador de carga (reemplaza al icono en loading).
- **Variants:** primary (**el** paso destacado; uno por pantalla) · secondary (acción alternativa, contorno) · tertiary (discreta, estilo texto) · on-band (sobre `bg.band`) · **icon** (solo ícono: cerrar, **↑ ↓**).
- **Sizes:** sm 36px (acciones de fila) · md 40px (default) · lg 46px (paso destacado; default en mobile para el paso destacado). **En mobile, el botón del paso destacado ocupa el ancho completo.**
- **States:** default · hover (pendiente) · focus (`focus.ring` + `border.focus`) · active (pendiente) · disabled (`bg.disabled` + `text.disabled`) · loading (label de carga + indicador; no clickeable).
- **Spacing:** gap ícono–label `space.inline.sm`; entre botones `space.inline.md`; ancho mínimo 88px; el label no se corta.
- **Accesibilidad:** `<button>` nativo; `aria-busy="true"` en loading; `variant="icon"` exige `aria-label` traducido; Enter y Espacio activan; anillo de foco siempre visible; en loading se anuncia el label de carga; **área táctil ≥ 44×44px en mobile (sm sube a 44px de alto en mobile)**.
- **Contenido:** verbo + objeto, sentence case; máx. ~30 caracteres; textos del catálogo.
- **Do:** un solo primary por pantalla; mostrar el label de carga. **Don't:** dos primary juntos; deshabilitar sin explicar por qué (mostrar el motivo cerca — acá: "Puedes modificarlo hasta el cierre de la votación." junto a "Reenviar"); emojis como ícono.
- **API:** `variant`, `size`, `loading`, `loadingLabel`, `disabled`, `iconStart`/`iconEnd`, `fullWidth`, `type`, `onClick`.

#### Componente: Callout (spec v2.0.0, completa)

- **Propósito:** aviso dentro del flujo. Cubre InfoCallout ("¿Cómo cuenta tu voto?"), avisos de consecuencias y ErrorBlock con reintento. Cuándo NO: confirmación efímera → toast; decisión → dialog; estado de entidad → status-pill.
- **Anatomía:** Container (`radius.field`) · Ícono por tono · Título opcional · Texto · Acción opcional (button tertiary).
- **Variants:** info (`bg.surface.subtle` + `border.default`, ícono `text.action`) · warning (`bg.warning.subtle` + `text.warning`) · error (`bg.surface` + `border.error` + `text.error`) · success (`bg.success.subtle` + `text.success`; "Recibimos tu …").
- **Sizes:** uno; padding `space.md`. **States:** default · con acción · busy.
- **Spacing:** gap ícono–texto `space.ms`; margen con el bloque al que refiere `space.sm`.
- **Accesibilidad:** `error` → `role="alert"`; `warning` de consecuencia asociado con `aria-describedby`; `info` sin rol; ícono `aria-hidden`.
- **Contenido:** una idea por callout; errores = qué pasó + qué hacer; nunca texto técnico del backend.
- **Do:** ubicar el error en el bloque que falló. **Don't:** reemplazar un error por un estado vacío; apilar varios callouts del mismo tono.
- **API:** `tone`, `title`, `children`, `action {label, onClick, busy?}` (+ `id` en el código).

#### Guía de accesibilidad (`guidelines/accessibility.md`, v0.1.0 placeholder — copiada)

Objetivo **WCAG 2.2 AA**. Contraste texto ≥ 4.5:1 (grande ≥ 3:1), componentes interactivos ≥ 3:1; no
comunicar estado solo con color. Teclado: todo interactivo accesible, foco visible, orden lógico,
Enter/Space activan, sin keyboard traps. Screen readers: rol ARIA correcto, íconos decorativos
`aria-hidden`, funcionales con `aria-label`; **live regions para feedback dinámico
(`aria-live="polite"`)**. Motion: respetar `prefers-reduced-motion`. **Targets táctiles ≥ 44×44px,
spacing entre targets ≥ 8px.** i18n: soportar longitud variable de texto.
