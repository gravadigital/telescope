## Story Reference

- **Story:** [S-011](../stories/S-011.multilenguaje-navegacion-y-acceso.md)
- **Service:** web
- **Summary:** Monta la infraestructura que usan todas las pantallas del rediseño de REQ-003: i18n
  propio sobre `Intl` (`src/i18n/`, ADR-010) con catálogos `es` / `en` tipados, errores traducidos

### Hallazgos del código que condicionan el plan

Relevados al planificar (no están en la documentación y cambian cómo se implementa):

1. **`react/jsx-no-literals` ya falla en 4 primitivos de S-010.** Corriendo la regla sobre
   `src/components/ui/` aparecen 4 errores, todos por puntuación sin texto:
   `FileDropzone.tsx:71` (`·`), `FilterTabs.tsx:76` (`·`), `StatTile.tsx:38` (`/`) y
   `TextField.tsx:184` (`/`). No son textos traducibles. → **Decisión D-1.**
2. **ESLint sobre todo `src/` no pasa hoy.** `npx eslint --ext .ts,.tsx src` da 34 errores y 4
   warnings, casi todos en tests viejos (`testing-library/no-node-access`, etc.) y en pantallas
   v1.0. El build de CRA no los ve porque solo lintea el grafo de webpack (sin tests). En cambio,
   `src/components/ui`, `src/domain` y `src/config` (sin tests) pasan con `--max-warnings=0`.
   → **Decisión D-2.**
3. **Jest no chequea tipos.** CRA corre Jest con Babel: un test no puede probar que "el proyecto
   no compila". `npx tsc --noEmit -p .` **pasa limpio hoy** (exit 0), así que se puede usar como
   chequeo. → **Decisión D-3.**
4. **Los `code` de error de `docs/apis/api.yaml` viven en las `description`** de las respuestas
   ≥ 400, entre backticks (p. ej. `'`EVENT_NOT_FOUND` (también para un evento en `creation`
   ajeno)'`), más el `enum` de `MiddlewareError.error`. Extrayéndolos así salen 105 valores, de los
   cuales **`GOOGLE_CLIENT_ID` no es un código**: es la variable de entorno mencionada en la
   descripción del 5xx de `/api/v1/auth/google/verify`. Quedan **104 códigos**. El paquete
   `yaml` (2.8.2) ya está en `dependencies`. → **Decisión D-4.**
5. **Las guías de texto del DS son placeholders con voseo.** `guidelines/i18n.md` declara
   `es-AR` "Voseo" como default, `foundations/voice-tone.md` dice "Español rioplatense", y los
   screen.md traen microcopy con voseo ("¿No tenés cuenta?", "Volvé a donde dejaste…"). La story
   (CA-5) y ADR-010 piden **español neutro sin voseo ni marcas de género**: mandan la story y el
   ADR. El microcopy de los screen.md se convierte al pasarlo al catálogo.
6. **`Menu` (variant `actions`) no admite ítems seleccionados.** Solo `variant="select"` pinta ✓
   y usa `menuitemradio`. El menú de usuario mezcla acciones (Mis eventos, Cerrar sesión) con la
   elección de idioma, y el DS prohíbe submenús. → **Decisión D-5.**
7. **No hay ícono de menú (hamburguesa).** `components/ui/icons/Icons.tsx` exporta `CloseIcon`,
   `MinusIcon`, `PlusIcon`, `CheckIcon`, `SearchIcon`, `UploadIcon`, `ChevronDownIcon`, `DotIcon`.
   Se agrega `MenuIcon` con el mismo `BaseIcon`.
8. **El product-map pone "Notificaciones" en el menú de usuario** y la campana en la barra. La
   story limita esta entrega a un **espacio** para la campana (CA-9) y no lista "Notificaciones"
   en el menú: ambos los completa S-018 (la ruta `/notifications` no existe todavía).
9. **`/my-events` no existe hasta S-013.** "Mis eventos" del menú (CA-9) navega a `/my-events`,
   que hasta S-013 cae en la 404. Es esperado; no se oculta el ítem.
10. **Las páginas de auth no llevan barra** según el product-map (layout dividido, S-06 a S-10).
    Las páginas provisorias de esta story no tienen ese layout. → **Decisión D-6.**
11. **Tests viejos mockean `useAuth` con `openAuthModal: jest.fn()`** (`ManageEventPage.test.tsx:117`,
    `Auth.test.tsx:25`, `AuthForm.test.tsx:36`, `VotingResultsPanel.test.tsx:23`), todos con
    `as any`. No rompen la compilación, pero quedan como referencia a algo que deja de existir:
    se limpian.
12. **`public/index.html` declara `<html lang="en">`.** El provider lo pisa al montar.
13. **El footer aparece en los screen.md** (`not-found`, `home`, `events-list`, `event-detail`,
    `my-events`, `notifications`) con "Telescopio · evaluación distribuida entre pares". Lo pone el
    `AppLayout` junto con la barra.
14. **El ancla de "Cómo funciona" todavía no existe.** El product-map apunta a
    `/#como-funciona`; la landing actual (inline en `App.tsx`) usa `id="how"`. La landing nueva y
    su ancla son de S-013. → **Decisión D-7.**
15. **`Modal` sigue en uso.** `pages/event-detail/EventDetailPage.tsx` importa
    `components/modal/Modal`; solo se quita su uso en `App.tsx`, no el componente.
16. **`stageNameKey` devuelve `string`.** Para que `t(stageNameKey(stage))` compile con claves
    tipadas, su retorno pasa a ser el literal `` `stages.${EventStage}.name` ``.

### Decisiones tomadas al planificar

- **D-1 — Puntuación permitida en la regla de lint.** `react/jsx-no-literals` se configura con
  `allowedStrings` para símbolos sin letras: `["·", "/", "—", "–", "×", "…", "→", "←", "↑", "↓",
  "+", "−", ":", "|", "(", ")", "%"]`. Los 4 primitivos de S-010 no se tocan. El chequeo TS-10 de
  `static-rules.test.ts` (texto con letras) sigue siendo el complemento para `ui/`.
- **D-2 — Lint acotado a las carpetas nuevas.** La regla vive en un `override` de `eslintConfig`
  (`package.json`) para `src/components/ui/**`, `src/components/layout/**`,
  `src/pages/not-found/**` y `src/pages/auth-page/**`, sin tests. Se agrega
  `"lint": "eslint --max-warnings=0 --ext .ts,.tsx --ignore-pattern '*.test.*' --ignore-pattern '__tests__' src/i18n src/domain src/components/ui src/components/layout src/pages/not-found src/pages/auth-page"`.
  Las stories de pantalla agregan su carpeta al override y al script. Como el build de CI corre con
  `CI=true`, un literal en esas carpetas también rompe `npm run build`.
- **D-3 — CA-4 se verifica con `tsc`.** Se agrega `"typecheck": "tsc --noEmit"` y un archivo
  `src/i18n/catalog.typecheck.ts` con casos `// @ts-expect-error` (clave faltante en `en`, clave
  extra, plural con forma de string). Si la derivación del tipo se rompiera, el `@ts-expect-error`
  queda sin usar y `tsc` (y el build, que chequea todo `src/`) fallan.
- **D-4 — Fuente de los códigos para el test de CA-8.** El test lee `docs/apis/api.yaml` con
  `yaml`, recorre `paths.*.*.responses` con status ≥ 400 (resolviendo `$ref` a
  `components.responses`), extrae de `description` los `` `[A-Z][A-Z0-9_]+` `` y suma
  `components.schemas.MiddlewareError.properties.error.enum`. Excluye una lista explícita
  `NOT_ERROR_CODES = ['GOOGLE_CLIENT_ID']`. Un código nuevo documentado en la api sin traducción
  rompe el test.
- **D-5 — Ítems radio dentro de un menú de acciones.** `MenuItem.selected` pasa a funcionar en
  `variant="actions"`: si un ítem trae `selected` definido (`true`/`false`), se renderiza con
  `role="menuitemradio"`, `aria-checked` y ✓ cuando es `true`; los demás siguen como `menuitem`.
  `variant="select"` no cambia. Es un cambio compatible (ningún uso actual pasa `selected` en
  `actions`).
- **D-6 — `/login` y `/register` provisorias dentro del `AppLayout`.** Hasta S-012 se ven con la
  barra (como hoy `/reset-password`): sin layout dividido no habría forma de volver. S-012 las saca
  del `AppLayout` al crear `AuthLayout`.
- **D-7 — "Cómo funciona" enlaza a `/#como-funciona` sin lógica de scroll.** El scroll y el foco al
  ancla los resuelve S-013 con la landing nueva.
- **D-8 — `useT()` falla fuera del provider**, igual que `useAuth`. Los tests usan un helper
  `renderWithProviders` (I18n + Auth mockeada + `MemoryRouter`).
- **D-9 — `next` rechaza también `/\`.** Además de la regla de la story (empieza con `/` y no con
  `//`), se rechaza cualquier `next` cuyo segundo carácter sea `\` (los navegadores tratan `/\host`
  como `//host`). Mismo destino por defecto: `/events`.
- **D-10 — Prefijo de clases `ly-` para `components/layout/`.** `static-rules.test.ts` suma
  `components/layout` a sus raíces (sin colores literales, sin medidas sueltas, sin texto propio) y
  acepta el prefijo `ly-`.

### Service Architecture (convenciones del servicio, copiadas)

**Estructura** (convención `project-structure`):

```
src/
├── App.tsx              # rutas, providers
├── index.tsx            # entry point (importa styles/tokens.css e index.css)
├── components/{kebab-case}/Component.tsx + Component.css
├── components/ui/       # primitivos del DS (S-010)
├── components/events/   # compuestos de dominio (S-010)
├── pages/{kebab-case}/PageName.tsx + PageName.css
├── context/             # React Context (AuthContext)
├── hooks/               # useLocalStorage, useFetch
├── domain/              # reglas puras (S-010): stages, files, dates, score, voting
├── services/api.ts      # llamadas por dominio
├── config/api.ts        # URL base, endpoints, apiRequest, ApiError
├── styles/tokens.css    # tokens DS v2.0.0 (única fuente)
└── types/index.ts       # tipos compartidos
```

- Carpeta en `kebab-case`, archivo del componente en `PascalCase`, un componente por carpeta con
  su CSS al lado.
- `export default` para el componente; tipos y helpers con export nombrado.
- Props tipadas en una `interface`; `React.FC<Props>` es el patrón mayoritario.
- `strict: true`: nada de `any` en código nuevo.
- **Sin `console.log`** en código nuevo; `console.error` solo para errores reales.

**Routing** (convención `routing`): todas las rutas en `src/App.tsx`, `BrowserRouter`.
`/events/:eventId/manage` va **antes** que `/events/:eventId`. Navegación de usuario con `<Link>`
(no `<a href>`, que recarga la app). `navigate(path, { replace: true })` sin entrada en el
historial. Excepción documentada: `AuthContext.logout()` usa `window.location.href = '/'`.

> Sobre rutas protegidas, la convención dice: "un componente que consuma `useAuth()`, **espere a
> que `loading` sea `false`** y devuelva `<Navigate … replace />` si no hay sesión. Esperar a
> `loading` es lo crítico: sin eso, un refresh expulsa al usuario antes de que se restaure la
> sesión desde `localStorage`." La story cambia el destino: `/login?next=<ruta>`.

**Estado** (convención `state-management`): `useState` local por defecto; Context solo si lo leen
ramas distintas del árbol (el idioma cumple: ADR-010). Persistencia en el navegador con
`useLocalStorage`. El patrón del modal de auth (`openAuthModal` + `registerAuthModalHandler`) **se
elimina** en esta story.

**Autenticación** (convención `auth`): `useAuth()` devuelve `{ user, token, isAuthenticated,
loading, login, logout, updateUser, joinEvent, openAuthModal }` — `openAuthModal` sale.
`useAuth` lanza fuera del provider. `logout()` limpia y hace `window.location.href = '/'`.
Claves de `localStorage`: `telescopio_user` (vía `useLocalStorage`, JSON) y `telescopio_token`
(directo). Expiración global por `CustomEvent('auth:logout')` (ADR-008), sin recarga.

**Manejo de errores** (convención `error-handling` + S-010): `apiRequest`, `uploadFile` y
`downloadFile` lanzan `ApiError { status, code?, message, details }`. Un fallo de red (fetch
rechazado) llega como el `TypeError` nativo, no como `ApiError`. **No manejar 401 en
componentes** (lo hace `apiRequest` + `AuthContext`).

**Estilado** (convención `styling` + DS v2.0.0): CSS plano por componente, clases globales con
prefijo por carpeta (`ui-`, `ev-`; esta story agrega `ly-`). Componentes nuevos **mobile-first**
con un único corte `@media (min-width: 768px)`; nunca `max-width`; sin hex ni medidas sueltas que
tengan token (lo verifica `static-rules.test.ts`).

**Testing** (convención `testing`): `.test.tsx` al lado del componente; consultas por rol / label /
texto, `userEvent` antes que `fireEvent`, `findBy*` para lo asíncrono; `jest.mock('../../services/api')`
para la API; `localStorage.clear()` en `beforeEach`. **No quitar el `moduleNameMapper` de
`package.json`** (react-router 7 en Jest 27). Comandos: `CI=true npm test` (desde `web/`),
`make test` (raíz).

### Relevant ADRs

**ADR-010: Internacionalización con un provider propio sobre `Intl`** (Aceptado, pendiente de
implementar — esta story lo implementa). Decisión, verbatim:

> `web/src/i18n/` con:
> - `I18nProvider` (Context) y `useT()`.
> - Catálogos `es.ts` y `en.ts`; **el tipo de `en` se deriva de `es`**, así una clave faltante no
>   compila.
> - Interpolación simple (`{name}`) y plurales con `Intl.PluralRules`.
> - Fechas con `Intl.DateTimeFormat` / `Intl.RelativeTimeFormat` y números con `Intl.NumberFormat`
>   (los helpers de `web/src/domain/` reciben el idioma).
> - Idioma inicial de `navigator.language` (`es*` → español; si no, inglés), persistido en
>   `localStorage` con `useLocalStorage`; `<html lang>` se actualiza al cambiar.
> - Errores de la api traducidos por `code` (`errors.<code>`), con fallback genérico; nunca se
>   muestra `err.message`.
> - Verificación: lint contra texto embebido en JSX en las carpetas nuevas y un test que rechaza
>   formas de voseo en el catálogo `es`.

Consecuencias negativas aceptadas: lo que trae una librería (namespaces, carga diferida, detección
avanzada) queda a cargo del equipo; todo el catálogo viaja en el bundle. Alternativas descartadas:
`react-i18next`, `FormatJS`/`react-intl`.

**ADR-008: Manejo global de expiración de sesión por CustomEvent** (implementado). Reglas que esta
story no debe romper: `apiRequest` ante 401 limpia `telescopio_user`/`telescopio_token` y emite
`auth:logout`; `AuthContext` lo escucha y desloguea **sin recargar**. Consecuencia en esta story:
si la sesión expira estando en una ruta con `RequireAuth`, el guard redirige a
`/login?next=<ruta actual>` (comportamiento deseado).

**ADR-006 (CRA)** y **ADR-007 (CSS plano sin framework)**: sin dependencias nuevas de UI ni de
estado; esta story no agrega ninguna dependencia.

### API Context

**Sin cambios de API.** Esta story no llama endpoints nuevos. Lo que consume de la api es su
**contrato de errores**, copiado de `docs/apis/api.yaml`:

```yaml
ApiError:            # forma de los handlers
  properties:
    error: { type: string, description: Mensaje legible }
    code: { type: string, description: 'Identificador en SCREAMING_SNAKE' }
    details: { oneOf: [string, object] }   # objeto en INVALID_STAGE_FOR_EDIT
  required: [error]

MiddlewareError:     # forma B: auth y permisos — `error` ES el código, nunca trae `code`
  properties:
    error: { type: string, enum: [UNAUTHORIZED, FORBIDDEN, BAD_REQUEST, NOT_FOUND] }
    message: { type: string }
  required: [error, message]

LegacyError:         # endpoints de votación distribuida: sin `code`
  properties:
    error: { type: string }
    details: { type: string }
    current_stage: { $ref: Stage }
  required: [error]
```

`ApiError` (cliente, S-010) normaliza las tres: `code` = `body.code`; o, si `body.error` es
SCREAMING_SNAKE y hay `body.message`, `code` = `body.error` (forma B); si no, `code` queda
`undefined` (forma legacy → mensaje genérico).

### Flow Context

La story no modifica flujos de sistema ("Flujos Afectados: Ninguno a nivel de sistema"). Flujos
de interacción de la story (verbatim):

**Escenario: Pantalla protegida sin sesión (CA-12, CA-13)** — Trigger: un visitante abre
`/events/create` desde un enlace.
1. **[web — `RequireAuth`]** espera `loading === false`; sin usuario → `navigate('/login?next=%2Fevents%2Fcreate', { replace: true })`.
2. **[web — login]** tras autenticarse, valida que `next` empiece con `/` y no con `//` →
   `navigate(next)`; si no, `/events`.

Outcome: el usuario llega a la pantalla pedida.

**Escenario: Cambio de idioma (CA-2)**
1. **[web — `UserMenu` o barra]** el usuario elige "Español".
2. **[web — `I18nProvider`]** actualiza el estado, guarda en `localStorage` y cambia
   `document.documentElement.lang`.
