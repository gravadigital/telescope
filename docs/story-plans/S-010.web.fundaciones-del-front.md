### Hallazgos del código que condicionan el plan

Relevados al planificar (no están en la documentación y cambian cómo se implementa):

1. **Colisión de nombres de variables CSS.** Los tokens viejos usan los mismos nombres que
   tendrían los primitivos del DS v2.0.0 con **valores distintos**: `--color-gray-50…700`
   (p. ej. viejo `--color-gray-500: #6b7280` vs DS `color.gray.500 = #6E7687`), `--radius-sm`
   (4 vs 8px), `--radius-md` (8 vs 10px), `--radius-xl` (16 vs 14px), `--radius-2xl` (24 vs
   18px) y `--font-family-mono`. Como todo vive en `:root`, gana la última definición y una de
   las dos partes (pantallas viejas o componentes nuevos) se vería mal. → **Decisión D-1.**
2. **Fallbacks que se activarían.** `components/stage-advance-modal/StageAdvanceModal.css` usa
   `var(--text-primary, #fff)` y `var(--text-secondary, #888 | #aaa)` (13 líneas) y
   `var(--surface-color, #1a1a2e)`. Hoy esas variables no existen y se usa el fallback. El token
   semántico `text.primary` del DS se llama `--text-primary` y vale `#0B1020` (tinta oscura): al
   definirlo, el texto del modal viejo pasaría a oscuro sobre fondo oscuro. → **Decisión D-2.**
3. **`index.css` y `global.css` no son idénticos.** La documentación dice que las 57 variables
   de `index.css` están repetidas "con idénticos valores" en `global.css`, pero dos difieren:
   `--color-gray-300` (`#d1d5db` en `index.css`, `#e8eaed` en `global.css`) y
   `--color-gray-400` (`#9ca3af` vs `#c4c9d4`). → **Decisión D-3.**
4. **`ApiRequestError` ya existe.** S-007 (web) agregó a `apiRequest` un `Error` con `status` y
   `code` (`interface ApiRequestError`, `getErrorCode`), con 6 tests en `config/api.test.ts`. Esta
   story lo convierte en la clase `ApiError` sin romper esos tests ni `getErrorCode`
   (`services/api.ts:638` lo usa). → **Decisión D-4.**
5. **`components/event-detail/EventDetail` no existe.** CA-12 dice "si existe": no hay nada que
   borrar. `ApiStatusAuth.tsx` y `voting/Voting.tsx` existen y no tienen referencias.
6. **`tsconfig.json` tiene `lib: ["dom", "dom.iterable", "es6"]`.** Con eso TypeScript no conoce
   `Intl.RelativeTimeFormat` (es2020.intl) que pide CA-10 (`dates.ts`). → se agrega `"es2020"` a
   `lib` (solo tipos; `target` sigue en `es5` y Babel compila).
7. **Ya existe `src/components/events/Events.tsx`** (listado viejo, con textos embebidos y hex).
   Los compuestos nuevos van en subcarpetas (`src/components/events/event-hero/` …), y los chequeos
   estáticos de CA-2 / CA-4 recorren solo las carpetas nuevas, no `Events.tsx`.
8. **Clases globales viejas con nombres genéricos**: `global.css` define `.card`, `.badge`,
   `.alert`, `.modal`, `.btn`, `.form-group`… Un componente nuevo con clase `card` heredaría esos
   estilos. → prefijo obligatorio (D-5).

### Decisiones tomadas al planificar (modo automático)

- **D-1 — Nombres de los tokens en `tokens.css`.** Regla única: el nombre CSS es la ruta del token
  con `.` → `-`.
  - **Tier 1 (reference) lleva prefijo `--ref-`**: `--ref-color-violet-700`, `--ref-radius-md`,
    `--ref-space-sm`, `--ref-font-size-md`, `--ref-shadow-1`… El prefijo elimina todas las
    colisiones del hallazgo 1 y deja explícito que es un primitivo.
  - **Tier 2 (semantic) y tier 3 (component) sin prefijo**: `--bg-surface`, `--text-primary`,
    `--border-focus`, `--radius-surface`, `--shadow-dialog`, `--focus-ring`, `--space-stack-md`,
    `--button-primary-bg`, `--dialog-backdrop`… Ninguno colisiona con el bloque legacy (verificado
    contra las 79 variables de `global.css` y las 57 de `index.css`).
  - Tipografía semántica como `font` shorthand con prefijo `--type-` (para no mezclar con los
    colores `--text-*`): `--type-display`, `--type-heading-l`, `--type-heading-m`,
    `--type-heading-s`, `--type-body`, `--type-ui`, `--type-caption`, `--type-eyebrow`,
    `--type-metric`, más `--type-tracking-tight` / `--type-tracking-wide` (el shorthand no incluye
    `letter-spacing` ni `text-transform`).
  - **Qué consume un componente:** colores, bordes, radios de superficie/control y sombras
    **solo** vía tier 2/3. Las escalas no cromáticas que las specs del DS citan directamente
    (`space.sm`, `font.size.2xl`, `radius.xs`…) se consumen vía `--ref-space-*`,
    `--ref-font-size-*`, `--ref-font-weight-*`, `--ref-radius-xs/sm` — es lo que hacen las specs.
    **Nunca `--ref-color-*` desde un componente.**
  - Breakpoint: `--ref-bp-desktop: 768px` y el alias documental de DA-7 `--bp-mobile: 768px`. En
    `@media` se escribe el literal `768px` con `min-width` (no hay variables en media queries).
  - Z-index (de `elevation.md`): `--ref-z-raised: 10`, `--ref-z-popover: 30`,
    `--ref-z-dialog: 40`, `--ref-z-toast: 50` → semánticos `--z-popover`, `--z-dialog`, `--z-toast`.
- **D-2 — Fallbacks de `StageAdvanceModal.css`.** Se reemplazan los `var(--text-primary, X)`,
  `var(--text-secondary, X)` por el literal `X` que hoy se ve (mismo render). No se toca nada más de
  ese archivo (lo borra S-016). `var(--surface-color, …)` y `var(--bg-primary, …)`
  (`ResetPasswordPage.css`) no colisionan con D-1 y quedan como están.
- **D-3 — Valor efectivo de `gray-300` / `gray-400`.** El bloque legacy conserva **el valor que hoy
  se ve**. `index.css` hace `@import './styles/global.css'` en la línea 95; css-loader emite el
  módulo importado **antes** que el que importa, así que hoy gana `index.css` (`#d1d5db`,
  `#9ca3af`). El implementador lo verifica en el CSS compilado (`npm run build` →
  `build/static/css/main.*.css`: buscar cuál `:root` aparece último) antes de consolidar.
- **D-4 — Forma de `ApiError`.**
  - `class ApiError extends Error { status: number; code?: string; details: Record<string, unknown> }`,
    con `name = 'ApiError'` y `Object.setPrototypeOf(this, ApiError.prototype)` (seguro con
    `target: es5`).
  - `message` = `body.error || body.message || 'HTTP error! status: N'` — **igual que hoy**, para
    que las pantallas que leen `err.message` (y el test TS-4 existente, que espera
    `"UNAUTHORIZED"`) sigan funcionando (CA-11).
  - `code`: `body.code` si es string; si no, **solo para la forma B** (`message` string y `error`
    en `SCREAMING_SNAKE`, regex `^[A-Z][A-Z0-9_]*$`) `code = body.error`; en cualquier otro caso
    `undefined`. Así `code = body.code ?? body.error` aplica a la forma B como pide CA-11 sin
    convertir en `code` el texto de la forma C (`{ error: "Event not found" }`), que el test
    TS-2 existente espera `undefined`.
  - `details`: el resto del body sin `error`, `code` ni `message` (p. ej.
    `{ current_stage: "voting" }`, o `{ details: "…" }` si el backend manda `details`). Body no
    JSON → `{}`.
  - `uploadFile` y `downloadFile` también lanzan `ApiError` (mismo constructor), para que la carga
    de propuesta (S-015) traduzca `FILE_TOO_LARGE` / `INVALID_FILE_TYPE` por `code`.
  - `ApiRequestError` queda como alias de tipo (`export type ApiRequestError = ApiError`) y
    `getErrorCode` se mantiene (prefiere `instanceof ApiError`).
  - Se eliminan los `console.log` de diagnóstico de `apiRequest` (incluido el preview del token),
    como pide la convención `project-structure` → Logging. Se mantiene el `console.error` de fallo.
- **D-5 — Prefijo de clases.** Primitivos: `ui-{kebab}` con BEM (`ui-button`,
  `ui-button--primary`, `ui-button__label`). Compuestos de evento: `ev-{kebab}` (`ev-hero`,
  `ev-stage-timeline`, `ev-next-step`, `ev-progress-checklist`). Ningún selector sin prefijo en los
  CSS nuevos.
- **D-6 — Textos por props (CA-4).** Donde la API del DS da un valor que implica texto propio, se
  agrega la prop de texto: `Dialog.closeLabel`; `TextField.optionalLabel`, `clearLabel`,
  `showPasswordLabel` / `hidePasswordLabel`; `NumberStepper.decrementLabel`, `incrementLabel`,
  `recommendedLabel`, `rangeError`; `DateQuickPicker.presets` pasa de `number[]` a
  `{ days: number; label: string }[]` y suma `changeLabel`; `FileDropzone.labels`;
  `StatTile.accessibleText`; `FilterTabs.options[].accessibleLabel`; `DataTable.columns[].header`
  (ya en el DS). Los íconos (cerrar, −, +, ✓, buscar, subir) son SVG inline con
  `aria-hidden="true"`, no glifos de texto. Separadores tipográficos (` · `, `/`) se permiten.
- **D-7 — Íconos.** `iconography` sigue en placeholder (pendiente conocido #3 del DS). No se agrega
  librería: los primitivos que necesitan un ícono fijo (cerrar, −/+, check, buscar, subir, chevron)
  usan un SVG inline mínimo en `src/components/ui/icons/Icons.tsx` (`stroke="currentColor"`,
  20px = `icon.md`). `EmptyState.icon` y `Button.iconStart/iconEnd` reciben `ReactNode`.
- **D-8 — Hover pendiente.** `bg.action.primary.hover` no está definido en el DS. Se declara
  `--bg-action-primary-hover: var(--bg-action-primary)` con comentario `/* Pendiente DS */`: el
  primario no cambia de color en hover hasta que el DS lo defina. No se inventa un valor.
- **D-9 — Clave de nombre de etapa.** `stageNameKey(stage)` devuelve `stages.<stage>.name`
  (S-011 crea el área `stages.*`; el sufijo `.name` deja lugar a `stages.<stage>.pill` y
  `.subtitle` que usan las pantallas).
- **D-10 — Reglas de avance en el cliente.** `validateStageAdvance` replica las del backend
  (`PATCH /stage`) y devuelve **los mismos `code`** del backend (`INVALID_TRANSITION`,
  `MISSING_ESTIMATED_DATE`, `INVALID_ESTIMATED_DATE`, `INSUFFICIENT_ATTACHMENTS`) para que la
  pantalla los traduzca con el mismo `errors.<code>` de S-011. La fecha estimada vale si es **hoy o
  posterior** (el backend: `parsedDate.Before(today)` → error).
- **D-11 — Umbrales.** `validateThresholds` replica el cálculo del backend en centésimos
  (`Math.round(x * 100)`), no con resta de floats: `0.7 - 0.6` en JS es `0.0999…` y daría un falso
  error.
- **D-12 — Fuentes.** Plus Jakarta Sans (400, 500, 600, 700, 800) y JetBrains Mono (400, 500, 600)
  desde Google Fonts con `display=swap`, con `<link rel="preconnect">` en `public/index.html`. No se
  cambia la fuente del `body` viejo: solo los componentes nuevos usan `--ref-font-family-base`.
- **D-13 — `StageTimeline` compacto.** `home.md` pide una "StageTimeline en versión compacta" para
  el destacado de Inicio. Se agrega `variant: 'full' | 'compact'` para que S-013 no cree otra.

- `localStorage.clear()` en `beforeEach` si el test toca sesión.
- Correr: `CI=true npm test` desde `web/` (o `make test` desde la raíz).

### Relevant ADRs

**ADR-007: CSS plano con variables, sin framework ni librería de componentes** (enmendado por
REQ-003)
- Decisión: un archivo `.css` por componente, importado desde su `.tsx`; tokens como variables CSS
  en `:root`; sin Tailwind, sin CSS-in-JS, sin CSS Modules, sin librería de componentes.
- Reglas de la enmienda (verbatim):
  - **Una sola fuente de tokens:** `web/src/styles/tokens.css`, con los tokens del DS `web` v2.0.0.
    Se elimina la copia de `index.css`. Las variables viejas quedan en un bloque *legacy* de
    `global.css` hasta que se reemplace la última pantalla (S-016 / S-017) y entonces se borran.
  - **Sin hex literales** en los componentes nuevos.
  - **Lenguaje visual nuevo:** de glassmorphism oscuro a "bandas oscuras + contenido claro" (paleta
    `#4B3FA8` / `#6E5BF2`, acento `#35D6F2`). Cambio breaking del DS → `web` v2.0.0.
  - **Breakpoints como escala nombrada** (`--bp-mobile: 768px` documentado; en `@media` se usa el
    literal) y **mobile-first** en los componentes nuevos.
  - **Componentes en vez de sistemas de clases:** `web/src/components/ui/` con los primitivos del DS
    (`Button`, `TextField`, `Dialog`, `DataTable`, …) y compuestos de dominio en
    `web/src/components/{dominio}/`. `Dialog` reemplaza las tres implementaciones de overlay con
    `role="dialog"`, foco atrapado y Escape (resuelve la deuda de accesibilidad de los overlays).
  - **Prefijo de clase por componente** para evitar colisiones.
  - *Alternativa considerada:* CSS Modules. Se descarta **en este REQ** para no cambiar la técnica a
    la vez que el lenguaje visual y todas las pantallas.

**ADR-008: Manejo global de expiración de sesión por CustomEvent**
- Decisión: ante un `401`, `apiRequest` limpia `telescopio_user` y `telescopio_token` de
  `localStorage` y emite `window.dispatchEvent(new CustomEvent('auth:logout', { detail: { reason:
  'token_expired' } }))`. `AuthContext` lo escucha y desloguea sin recargar.
- Regla para esta story: **`ApiError` no cambia este comportamiento**. El test TS-4 existente de
  `config/api.test.ts` debe seguir pasando.

**ADR-010: Internacionalización con un provider propio sobre `Intl`** (pendiente de implementar,
S-011)
- Aplica a esta story en dos puntos:
  - "Fechas con `Intl.DateTimeFormat` / `Intl.RelativeTimeFormat` y números con `Intl.NumberFormat`
    (los helpers de `web/src/domain/` reciben el idioma)."
  - "Errores de la api traducidos por `code` (`errors.<code>`), con fallback genérico; nunca se
    muestra `err.message`." → por eso `ApiError` conserva `code`.
- Los componentes de esta story **no importan i18n** (S-011 todavía no existe): reciben todo texto
  por props (CA-4).

**ADR-006: Create React App** — se mantiene CRA; no se eyecta ni se agrega configuración de
webpack/Jest más allá de lo existente.

### API Context

Esta story no agrega ni cambia endpoints. Consume la forma de los errores y referencia el preview
de votación.

**Formas de error que `ApiError` normaliza** (de `docs/apis/api.yaml` y la convención
`api/error-handling`):

| Forma | Ejemplo | `message` | `code` | `details` |
|---|---|---|---|---|
| A (handlers) | `{ "error": "Invalid request payload", "code": "INVALID_PAYLOAD", "details": "..." }` | `"Invalid request payload"` | `"INVALID_PAYLOAD"` | `{ details: "..." }` |
| A con extras | `409 { "error": "...", "code": "INVALID_UPDATE_STAGE", "current_stage": "voting" }` | `error` | `"INVALID_UPDATE_STAGE"` | `{ current_stage: "voting" }` |
| B (middlewares) | `401 { "error": "UNAUTHORIZED", "message": "Missing Authorization header" }` | `"UNAUTHORIZED"` | `"UNAUTHORIZED"` | `{}` |
| C (degradada) | `{ "error": "Event not found" }` | `"Event not found"` | `undefined` | `{}` |
| Body no JSON | `502` con HTML | `"HTTP error! status: 502"` | `undefined` | `{}` |

##### Guidelines

**Do:**
- Usar el negro solo en bandas de identidad y navegación (header, EventHero, auth).
- Un solo elemento en `bg.action.primary` por pantalla: el paso destacado.
- Comunicar estado con texto además de color ("✓ Enviado", "Pendiente").
- Usar `text.inverse.secondary` y `text.signal` para jerarquía dentro de una banda.

**Don't:**
- No escribir hex literales en componentes (deuda #1 de la v1.0, RF 7).
- No poner contenido largo sobre `bg.band`: la banda es identidad, no lectura.
- No usar `bg.accent` como botón primario sobre fondo claro: el primario es `bg.action.primary`.
- No usar el cian sobre fondo claro (contraste insuficiente).

#### Button

##### Propósito

Dispara una acción. Es el componente `Button` de `src/components/ui/button/` (DA-8): reemplaza el
sistema de clases `.btn-*` de la v1.0.

**Cuándo usar:** acciones que cambian estado (inscribirme, enviar, abrir votación), el paso destacado de cada pantalla, acciones de diálogos.

**Cuándo NO usar:** navegación entre pantallas sin acción → link (`<a>` con `text.action`); acción solo icónica sin texto → `variant="icon"` con `aria-label`.

##### Anatomía

1. **Container** — rectángulo con `radius.control`.
2. **Label** — verbo + objeto ("Enviar propuesta").
3. **Icono (opcional)** — antes o después del label (→ en pasos que avanzan).
4. **Indicador de carga** — reemplaza al icono en `loading`.

##### Variants

| Variant | Propósito | Tokens | Ejemplo |
|---|---|---|---|
| primary | **El** paso destacado; uno por pantalla | `button.primary.*` | "Abrir inscripción →" |
| secondary | Acción alternativa (contorno) | `button.secondary.*` | "Cancelar", "Cerrar votación y publicar" mientras falten votos |
| tertiary | Acción discreta, estilo texto | `button.tertiary.*` | "Pausar evento", "Marcar todo como leído" |
| on-band | Acción sobre `bg.band` | `button.onBand.*` | "Compartir" en EventHero |
| icon | Solo ícono (cerrar, ↑ ↓) | `button.icon.*` | "×" de un diálogo |

`destructive` no existe: el producto no tiene acciones destructivas con tratamiento propio (cancelar evento está fuera de alcance).

##### Sizes

| Size | Alto | Padding | Uso |
|---|---|---|---|
| sm | 36px | `space.ms` horizontal | Acciones de fila de tabla, chips de acción |
| md | 40px | 18px horizontal | Default |
| lg | 46px | `space.lg` horizontal | Paso destacado, CTA de landing; default en mobile para el paso destacado |

En mobile, el botón del paso destacado ocupa el ancho completo.

##### States

| State | Descripción | Tokens |
|---|---|---|
| default | Base | `button.{variant}.bg/fg/border` |
| hover | Puntero encima | `button.primary.bg.hover` — **Pendiente** (el diseño no lo define) |
| focus | Teclado | `focus.ring` + `border.focus` |
| active | Presionado | Pendiente, junto con hover |
| disabled | No interactivo | `bg.disabled` + `text.disabled` |
| loading | Acción en curso | label de carga ("Enviando…") + indicador; no clickeable |

##### Spacing & sizing rules

- Gap ícono–label: `space.inline.sm`.
- Entre botones de un grupo: `space.inline.md`; en diálogos, el primario a la derecha (desktop) o arriba (mobile, en alertdialog).
- Ancho mínimo 88px; el label no se corta: si no entra, el botón crece.

##### Accesibilidad

- **ARIA:** `<button>` nativo. `aria-busy="true"` en loading. `variant="icon"` exige `aria-label` traducido.
- **Teclado:** Enter y Espacio activan.
- **Foco:** anillo `focus.ring` siempre visible.
- **Screen reader:** en loading se anuncia el label de carga.
- Área táctil ≥ 44×44px en mobile (sm sube a 44px de alto en mobile).

##### Guidelines de contenido

- Verbo en infinitivo o imperativo + objeto, sentence case: "Abrir votación y asignar".
- El botón de confirmación repite el verbo del título del diálogo, nunca "Confirmar" / "OK" (2b).
- Máximo ~30 caracteres; los textos vienen del catálogo i18n.

##### Do's & don'ts

**Do:** un solo primary por pantalla (el paso destacado) · secondary para la opción segura de un diálogo con el mismo peso visual (2f) · mostrar el label de carga.

**Don't:** dos primary juntos · deshabilitar sin explicar por qué (mostrar el motivo cerca) · usar tertiary para la acción principal · usar emojis como ícono.

| Prop | Tipo | Default | Descripción |
|---|---|---|---|
| variant | `primary \| secondary \| tertiary \| onBand \| icon` | `primary` | Variant |
| size | `sm \| md \| lg` | `md` | Tamaño |
| loading | boolean | false | Estado de carga |
| loadingLabel | string | — | Label en loading |
| disabled | boolean | false | Deshabilitado |
| iconStart / iconEnd | ReactNode | — | Íconos |
| fullWidth | boolean | false | Ancho completo |
| type | `button \| submit` | `button` | Tipo nativo |
| onClick | function | — | Acción |

#### TextField

##### Propósito

Campo de texto con etiqueta, ayuda y error. Cubre tres roles con una sola API: línea simple,
**multilínea con contador** (descripción, comentario) y **búsqueda** (con ícono).

**Cuándo usar:** formularios (crear evento, editar datos, auth), comentario de la propuesta, búsqueda del listado.

**Cuándo NO usar:** números acotados → [number-stepper](./number-stepper.md); fechas → [date-quick-picker](./date-quick-picker.md); elegir entre opciones → [filter-tabs](./filter-tabs.md) o [menu](./menu.md).

##### Anatomía

1. **Label** — `text.ui`, con "*" si es obligatorio o "(opcional)".
2. **Field** — `bg.surface`, `border.strong`, `radius.field`.
3. **Ícono inicial (opcional)** — búsqueda.
4. **Acción final (opcional)** — "Mostrar" / "Ocultar" en contraseña, limpiar en búsqueda.
5. **Contador (multilínea)** — "{n} / {max}".
6. **Ayuda** — `text.caption` / `text.muted`.
7. **Mensaje de error** — `text.error`, reemplaza a la ayuda.

##### Variants

| Variant | Propósito | Ejemplo |
|---|---|---|
| text | Línea simple (text, email, password) | Nombre del evento, Email |
| multiline | Texto largo con contador y alto mínimo de 4 líneas | Descripción (2000), Comentario (1000) |
| search | Ícono de búsqueda, sin label visible (label accesible), botón limpiar | "Buscar por nombre u organizador" |

##### Sizes

| Size | Alto | Uso |

<!-- docs/design-system/web/guidelines/accessibility.md -->

#### Accesibilidad

> **Placeholder inicial** — Reemplazar con specs reales del producto.

##### Propósito

Reglas transversales de accesibilidad. Aplican a todos los componentes y
pantallas. Cualquier excepción debe documentarse explícitamente.

##### Cumplimiento target

**WCAG 2.2 — Nivel AA** (mínimo).

Algunos criterios apuntar a **AAA** cuando es viable (contraste de texto largo,
keyboard navigation).

##### Áreas clave

###### Color y contraste
- Texto body (≥16pt): contraste ≥4.5:1.
- Texto grande (≥18pt o ≥14pt bold): contraste ≥3:1.
- Componentes interactivos (bordes, iconos): contraste ≥3:1.
- NO comunicar estado solo con color.

###### Teclado
- Todo elemento interactivo es accesible vía teclado.
- Foco visible (outline o equivalente, contraste ≥3:1).
- Orden de tab lógico (top → bottom, left → right en LTR).
- ESC cierra modales / popovers.
- Enter / Space activan controles.
- Sin keyboard traps.

###### Screen readers
- Cada componente declara su rol ARIA correcto.
- Iconos puramente decorativos: `aria-hidden="true"`.
- Iconos funcionales: `aria-label` descriptivo.
- Imágenes con contenido: `alt` real (no "image" o "photo").
- Live regions para feedback dinámico (`aria-live="polite"` o `assertive`).

###### Forms
- Cada input tiene un `<label>` asociado.
- Errores anunciados al screen reader (`aria-invalid`, `aria-describedby`).
- Helper text accesible vía `aria-describedby`.
- Required fields marcados con `aria-required="true"`.

###### Motion
- Respetar `prefers-reduced-motion: reduce`.
- No flashing >3 veces/segundo.
- Animaciones >5s deben ser pausables.

###### Targets táctiles
- Mínimo 44×44px (Apple) o 48×48px (Material).
- Spacing entre targets ≥8px.

###### Internacionalización
- Soportar texto en otros idiomas (longitud variable).
- Soportar RTL si aplica al locale del producto.
- Foco lógico se invierte en RTL (right → left).

##### Testing

- **Automatizado**: axe-core, Lighthouse, eslint-plugin-jsx-a11y.
- **Manual**: navegación 100% con teclado, screen reader real (VoiceOver, NVDA, TalkBack).
- **Audit**: incluir a11y en code review checklist.

export class ApiError extends Error {
  readonly status: number;
  readonly code?: string;
  readonly details: Record<string, unknown>;

  constructor({ status, body }: { status: number; body: unknown }) {
    const data: Record<string, unknown> =
      body && typeof body === 'object' && !Array.isArray(body) ? (body as Record<string, unknown>) : {};
    const error = typeof data.error === 'string' ? data.error : undefined;
    const text = typeof data.message === 'string' ? data.message : undefined;
    super(error || text || `HTTP error! status: ${status}`);
    Object.setPrototypeOf(this, ApiError.prototype);
    this.name = 'ApiError';
    this.status = status;
    if (typeof data.code === 'string') this.code = data.code;
    else if (error && text !== undefined && FORM_B_CODE.test(error)) this.code = error; // forma B
    const { error: _e, code: _c, message: _m, ...rest } = data;
    this.details = rest;
  }
}
